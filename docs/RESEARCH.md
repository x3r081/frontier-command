# Command & Conquer (Tiberian Dawn) mechanics research

This note describes the 1995 **Tiberian Dawn** gameplay model, using Westwood's [C&C95 manual (1998 OEM printing)](https://www.retrogames.cz/manualy/DOS/Command_and_ConquerCC_-_PC_-_Manual.pdf) and [EA's released Tiberian Dawn source](https://github.com/electronicarts/CnC_Tiberian_Dawn). The manual is primary game documentation even though this PDF is hosted by a preservation site. Numeric balance values below come from the manual's unit and structure charts; for engine edge cases, use the code as the arbiter. [OpenRA](https://www.openra.net/about/) is a separate modern interpretation, not a description of the 1995 rules.

**Scope distinction:** the mechanics and balance tables above describe the historical C&C reference, based on the linked manual and EA source. They do not describe Frontier Command's implementation. The final section is a separate audit of this project's checked-in source and assets, with current features and gaps identified explicitly.

The reference game has two asymmetric sides, GDI and Nod. Most missions are scenario driven. Some begin with an MCV or Construction Yard and allow production; some give a fixed force and require a different objective. Multiplayer offers faction/color selection, starting credits, and switches for bases, crates, Tiberium growth, and AI opponents. [Manual pp. 6, 9, 22, 42–43, 60–61](https://www.retrogames.cz/manualy/DOS/Command_and_ConquerCC_-_PC_-_Manual.pdf#page=7)

## Core game loop

1. Explore the shrouded map, locate Tiberium and the enemy.
2. Deploy the MCV into a Construction Yard, build power, then a Refinery. Each Refinery provides one Harvester.
3. Harvesters collect from a visible field, return to a Refinery, unload credits, and resume collecting. Protecting them and controlling resource fields are central strategic tasks.
4. Add infantry and vehicle production, tech structures, defenses, storage, and more power. Buildings extend the legal base-placement area.
5. Counter enemy armor, infantry, aircraft, and defenses with the appropriate weapons; raid economy or power; capture structures with Engineers; and meet the mission objective.

## Economy, production, and base building

| System | Original behavior |
| --- | --- |
| MCV / construction | Deploy an MCV on clear ground to create a Construction Yard. The yard enables structure construction. Completed structures are manually placed on a white/red grid adjacent to an existing owned structure. [Manual pp. 10–12](https://www.retrogames.cz/manualy/DOS/Command_and_ConquerCC_-_PC_-_Manual.pdf#page=11) |
| Production | The sidebar shows building and unit icons; the 1995 interface produces one structure and one unit at a time, charging during progress. Extra production structures can speed output, and the player can mark a particular factory as the primary exit point. [Manual pp. 11, 77, 83](https://www.retrogames.cz/manualy/DOS/Command_and_ConquerCC_-_PC_-_Manual.pdf#page=12), [factory code](https://github.com/electronicarts/CnC_Tiberian_Dawn/blob/main/FACTORY.CPP) |
| Tiberium / harvesters | Refinery costs 2,000, comes with a Harvester, and stores 1,000 credits of processed Tiberium. A Silo costs 150 and adds 1,500 storage. Overflow is lost. Harvesters can be directed to a field or ordered home early. Multiple Harvesters may share a Refinery, but docking is a bottleneck. [Manual pp. 14–16, 45](https://www.retrogames.cz/manualy/DOS/Command_and_ConquerCC_-_PC_-_Manual.pdf#page=15) |
| Regrowth / hazard | Tiberium cells increase density and mature patches spread into adjacent clear cells; blossom trees increase spread opportunities. Ordinary infantry standing in Tiberium take damage, while Chem Warriors are immune. The multiplayer host can toggle growth. [Map source](https://github.com/electronicarts/CnC_Tiberian_Dawn/blob/main/MAP.CPP), [infantry source](https://github.com/electronicarts/CnC_Tiberian_Dawn/blob/main/INFANTRY.CPP) |
| Spending and refund | Initial credits and harvested Tiberium are tracked separately in the engine, with harvested Tiberium consumed first. Repair spends credits over time. Selling a structure returns half its original cost; canceling unfinished production refunds unspent cost. [House source](https://github.com/electronicarts/CnC_Tiberian_Dawn/blob/main/HOUSE.CPP), [Manual p. 17](https://www.retrogames.cz/manualy/DOS/Command_and_ConquerCC_-_PC_-_Manual.pdf#page=18) |
| Power | Standard Power Plant: +100 power, 300 credits. Advanced Plant: +200, 700 credits. Construction Yard consumes 30; Barracks/Hand 20, Refinery 40, Factory/Airstrip 30, Radar/Comm 40. Damaged plants produce less. Deficit slows production, turns off radar, and disables advanced defenses and special-weapon charging. [Manual pp. 12–13, 51, 69](https://www.retrogames.cz/manualy/DOS/Command_and_ConquerCC_-_PC_-_Manual.pdf#page=13), [House source](https://github.com/electronicarts/CnC_Tiberian_Dawn/blob/main/HOUSE.CPP) |
| Repair / capture / sell | Structures can be repaired simultaneously while credits last. Repair Facilities fix vehicles. Engineers enter capturable enemy structures and transfer ownership, allowing remote base expansion and sometimes cross-faction production. Most defensive towers are not capturable. Selling deconstructs and refunds 50%. [Manual pp. 17–18, 76](https://www.retrogames.cz/manualy/DOS/Command_and_ConquerCC_-_PC_-_Manual.pdf#page=18) |

### Structure and tech outline

The original campaign also gates technology by mission or scenario level, so having a prerequisite building alone does not always unlock a unit. Multiplayer tech levels appear in the manual's charts. These are the principal build dependencies, not every scenario exception. [GDI chart pp. 50–51](https://www.retrogames.cz/manualy/DOS/Command_and_ConquerCC_-_PC_-_Manual.pdf#page=51), [Nod chart pp. 68–69](https://www.retrogames.cz/manualy/DOS/Command_and_ConquerCC_-_PC_-_Manual.pdf#page=69), [build legality code](https://github.com/electronicarts/CnC_Tiberian_Dawn/blob/main/HOUSE.CPP)

| Stage | GDI | Nod | Purpose |
| --- | --- | --- | --- |
| Base start | Construction Yard → Power Plant | Same | Construction radius and energy. |
| Economy | Refinery → Silo; extra Harvester from vehicle producer | Same | Income, storage, and throughput. |
| Infantry | Barracks → rifle, Grenadier, Rocket Soldier, Engineer | Hand of Nod → rifle, Flamethrower, Rocket Soldier, Engineer | Early army, anti-armor/air support, capture. |
| Vehicles | Weapons Factory → Humm-Vee, Medium Tank; Factory + Barracks → APC; Factory + Repair Facility → Mammoth | Airstrip → Bike, Buggy, Light Tank, Artillery; Airstrip + Comm Center → Flame/Stealth Tank | GDI manufactures locally; Nod vehicles arrive by cargo aircraft at an Airstrip. |
| Intelligence | Communications Center → radar; Advanced Communications Center → Ion Cannon | Communications Center → radar | Radar requires adequate power. |
| Air | Barracks + Helipad → Orca and rearming | Hand + Helipad → Apache and rearming | Aircraft use finite ammunition and return to a pad. Chinooks can carry five infantry. |
| Defense / late tech | Barracks → Guard Tower; Comm Center → Advanced Guard Tower and Advanced Comm/Ion Cannon; Factory + Advanced Comm → MLRS | Hand → Turret and SAM; Comm Center → Obelisk and Temple/Nuke; Airstrip + Obelisk → SSM | Higher tech is expensive and power sensitive. |

**Key structure costs and demands:** Construction Yard is supplied by deploying an MCV (MCV build cost 5,000). Refinery 2,000 / 40 power; Barracks or Hand 300 / 20; Weapons Factory or Airstrip 2,000 / 30; Communications Center 1,000 / 40; Silo 150 / 10; Helipad 1,500 / 10; Repair Facility 1,200 / 30; GDI Guard Tower 500 / 10; Advanced Guard Tower 1,000 / 20; Nod Turret 600 / 20; SAM 750 / 20; Obelisk 1,500 / 150; GDI Advanced Communications Center 2,800 / 200; Nod Temple 3,000 / 150. Walls are separate cheap placement items. [Manual pp. 51, 69](https://www.retrogames.cz/manualy/DOS/Command_and_ConquerCC_-_PC_-_Manual.pdf#page=52)

### Units and combat roles

Manual costs are in credits. Unit availability varies by mission; several advanced units appear only in multiplayer or as scripted mission units. [GDI unit chart pp. 42–43](https://www.retrogames.cz/manualy/DOS/Command_and_ConquerCC_-_PC_-_Manual.pdf#page=43), [Nod unit chart pp. 60–61](https://www.retrogames.cz/manualy/DOS/Command_and_ConquerCC_-_PC_-_Manual.pdf#page=61)

| Side | Unit (cost) | Role and defining behavior |
| --- | --- | --- |
| Both | Rifle Infantry (100), Rocket Soldier (300), Engineer (500) | Cheap anti-infantry; anti-armor/air; unarmed structure capture. |
| Both | Harvester (1,400), MCV (5,000), APC (700), Chinook (1,500), Commando (1,000) | Economy; new base; five-passenger ground/air transport; sniper plus building-demolition charges. Some are mission/multiplayer gated. |
| GDI | Grenadier (160), Humm-Vee (400), Medium Tank (800) | Explosive infantry against clusters/walls; fast anti-infantry vehicle; durable all-purpose armored core. |
| GDI | MRLS (800), Mammoth Tank (1,500), Orca (1,200) | Long-range rockets including anti-air; slow dual-cannon/missile heavy tank that regenerates up to 50%; limited-ammunition anti-armor helicopter. |
| Nod | Flamethrower (200), Recon Bike (500), Buggy (300), Light Tank (600) | Anti-infantry flame; fast rocket scout and anti-air; cheap machine-gun harassment; fast light armor. |
| Nod | Artillery (450), Flame Tank (800), Stealth Tank (900), Apache (1,200) | Inaccurate long-range splash; close-range anti-infantry/structures; cloaked missile ambush (revealed during fire or near infantry/Guard Towers); anti-infantry helicopter. |
| Nod late | Chem Warrior (300), SSM Launcher (750) | Tiberium-immune area poison; extreme-range incendiary launcher with slow reload. |

The [source's weapon and warhead tables](https://github.com/electronicarts/CnC_Tiberian_Dawn/blob/main/CONST.CPP) define damage, cooldown, range, and armor modifiers. Damage uses distinct unarmored, wood, aluminum, steel, and concrete classes, with distance falloff for area effects. Small arms are most useful against infantry; AP shells against steel armor; high explosive against infantry/buildings; fire against vulnerable infantry/structures. Therefore, a single scalar attack number would lose important counterplay. Track projectiles or hit timing, range, splash, armor class, facing/rotation where applicable, target eligibility for air/ground, and damage states. Large tracked vehicles can crush enemy infantry; damaged vehicles slow down. [Combat source](https://github.com/electronicarts/CnC_Tiberian_Dawn/blob/main/COMBAT.CPP), [Manual pp. 18, 33](https://www.retrogames.cz/manualy/DOS/Command_and_ConquerCC_-_PC_-_Manual.pdf#page=19)

## Visibility, orders, victory, and AI

- **Original visibility:** Units reveal initially black terrain within their sight radius. The source uses a radial distance check without modern terrain raycasting. The map records revealed cells persistently; it does not run the modern receding fog loop. Radar is a separate powered display. [Map source](https://github.com/electronicarts/CnC_Tiberian_Dawn/blob/main/MAP.CPP), [Display source](https://github.com/electronicarts/CnC_Tiberian_Dawn/blob/main/DISPLAY.CPP), [Manual p. 80](https://www.retrogames.cz/manualy/DOS/Command_and_ConquerCC_-_PC_-_Manual.pdf#page=81)
- **Original controls:** Left click selects and context-orders move/attack/enter/harvest/deploy; drag-box selects groups; right click deselects/cancels. `Ctrl+number` saves a control group, number recalls it, `Alt+number` centers it. `G` guards, `Ctrl+click` force-fires, `Alt+click` force-moves/crushes, `X` scatters, `S` stops, `N` cycles units, `Ctrl+Alt+click` follows/escorts. [Manual pp. 7–8, 32–33](https://www.retrogames.cz/manualy/DOS/Command_and_ConquerCC_-_PC_-_Manual.pdf#page=8)
- **Victory:** Campaign missions use scenario-specific trigger events: destroy all units/buildings, capture or evacuate civilians, reach credits, survive a timer, build an item, and so on. In multiplayer a player is defeated when their active buildings, infantry, vehicles, and aircraft are gone; allied survivors may win together. Avoid treating every mission as a simple Construction Yard kill. [House and trigger source](https://github.com/electronicarts/CnC_Tiberian_Dawn/blob/main/HOUSE.CPP), [trigger source](https://github.com/electronicarts/CnC_Tiberian_Dawn/blob/main/TRIGGER.CPP)
- **Original AI:** Scripted teams, trigger-based reinforcements, and periodic/alert-driven attacks are central in campaign. The AI makes build choices from desired team composition and can replace a lost Harvester when it has a Refinery; difficulty changes attack timing. A useful modern skirmish opponent should also maintain economy, place power/tech/defenses, escort harvesters, choose target priorities, and attack in coherent waves. [House source](https://github.com/electronicarts/CnC_Tiberian_Dawn/blob/main/HOUSE.CPP), [team source](https://github.com/electronicarts/CnC_Tiberian_Dawn/blob/main/TEAM.CPP)

## Original rules versus optional modernization

| Feature | 1995 behavior | Optional modern UX / balance choice |
| --- | --- | --- |
| Visibility | Permanent shroud removal by radius; powered radar. | Receding fog, terrain-blocked line of sight, explored-but-out-of-sight tint, last-seen contacts. |
| Orders | Classic left-click context actions, guard/force fire/force move/scatter/follow. | Right-click option, attack-move, unit stances, explicit command bar. |
| Production | Limited simultaneous production, no modern queue interface. | Multiple queues, repeat production, clear/rally markers, pause/resume controls. |
| Unit progression | No general veterancy progression in the original core loop. | Veterancy and achievements. |
| Match viewing | Campaign saves and multiplayer options. | Replays, observers, accessible hotkeys, colorblind overlays, tactical pause. |

[OpenRA's own project description](https://www.openra.net/about/) explicitly lists right-click controls, production queues, attack-move, stances, receding fog, veterancy, replay/observer support, and balance changes as modernization. If implemented, label them as deliberate changes instead of claiming exact classic behavior.

### Follow-up implementation, 2026-10-04

### Online deployment constraints

`npm run dev` runs the Node server and Vite together. A complete production deployment uses `npm run build` followed by `npm start`; the same Node process serves the static build, JSON API, and WebSocket endpoint. `npm run preview` serves the built client only and does not provide online services. The default JSON store is `server/data.json` (override with `FRONTIER_DATA_FILE`); `PORT` and `HOST` configure the listener. Production multiplayer needs WebSocket support, one authoritative server instance, and persistent writable storage. Active matches checkpoint to that store and can recover after a short process restart, while waiting lobbies remain in memory. Ephemeral/serverless hosting can discard profiles, scores, and match checkpoints; multiple uncoordinated instances can split profile connections and room state. Static hosting or Vite preview alone supports local play only, not online features.

Frontier Command is an original RTS that borrows broad genre conventions. It should not be described as a complete Tiberian Dawn copy: the faction roster, mission structure, air transport rules, multiplayer, original command set, campaign triggers, and many historical rules differ or are absent.

The [EA source repository](https://github.com/electronicarts/CnC_Tiberian_Dawn) is licensed under GPLv3 with additional terms and does not grant blanket rights to Westwood/EA art, audio, cinematics, names, or marks. This project should build an original visual and audio identity and treat source/manual content as mechanics research unless reuse rights are deliberately checked.
